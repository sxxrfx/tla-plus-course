The next-state relation is a formula, not a command.

{{lesson:states}} ended with an English description of the tiny program's state machine. It is neither precise nor practical. Rewriting it as math gives you something that is simply true or false for each pair of states.

That is the destination, shown in the diagram: a formula, and two pairs of states it is true or false for. The rest of this lesson builds the formula and then explains these two verdicts.

Why math?

Asked what a specification language should look like, most programmers want something like their favorite programming language. TLA+ uses ordinary, simple math instead, and most programmers first find that a bad idea. The team behind the real-time operating system from {{lesson:why}} started out biased toward a C-like language and saw the math as a hindrance. They ended up calling it a major benefit, because it forced them to reason more abstractly about the system.

The initial values

The initial values are i equal to 0 and pc equal to "start". The word “and” becomes a math operator, which is && in some programming languages and ∧ in math. In the ASCII you type, it is /\:

(i = 0) /\ (pc = "start")

Turning the relation into notation

The English relation needs a handful of replacements:

EnglishNotationNote
current value of pcpcAn unprimed variable means its value in the current state.
next value of pcpc'Read “pc prime”: its value in the next state.
equals=Plain equality, as in 2 + 2 = 4.
in\in“Is an element of,” written ∈ in math.
{0, 1, ..., 1000}0..1000“...” is informal. .. is a precisely defined operator.
the two lines of a then clause/\There is an implicit “and”: both must be true.
no next valuesFALSESee below.

The last row needs thought. “No next values” must become a formula that isn't true for any values of i, pc, i', and pc'. The simplest is the formula that is always false: FALSE. Most TLA+ keywords are uppercase, so the result, as you would type it in ASCII, is:

IF pc = "start"
  THEN (i' \in 0..1000) /\
       (pc' = "middle")
  ELSE IF pc = "middle"
         THEN (i' = i + 1) /\
              (pc' = "done")
         ELSE FALSE

How to read it

The formula relates four values: i, pc, i', and pc'. It does not mean “if pc equals start, do the THEN part, otherwise do the ELSE part.” It means that if pc equals "start", the value of the whole formula equals the value of the THEN formula, and otherwise it equals the value of the ELSE formula.

Use the tree to check the two pairs in the first diagram.

The true pair: i = 17, pc = "start", i' = 534, pc' = "middle". The first test is true, so the tree goes to the first THEN formula. 534 is in 0..1000 and pc' is "middle", so both parts are true and the formula is true. You may have noticed that i = 17 with pc = "start" never occurs when the program runs, since i starts at 0. That doesn't matter here: the formula has a value for any four values you give it.

The false pair: i = 534, pc = "middle", i' = 77, pc' = "done". The first test is false and the second is true, so the tree goes to the second THEN formula. pc' is right, but 77 does not equal 534 + 1, so the formula is false.

Predict: what is the value for i = 5, pc = "middle", i' = 6, pc' = "middle"?

False. The second test is true and i' = i + 1 holds, but pc' = "done" does not. An “and” needs both parts.

Predict: what is the value for i = 43, pc = "done", i' = 44, pc' = "done"?

False. Both tests are false, so the formula equals its last ELSE, which is FALSE. Any values of i' and pc' give the same answer when pc is "done", and that is what “no next values” means here.

How many next states?

Since the formula is just true or false for each pair, you can ask, for a given current state, how many next states make it true.

In the diagram, the start state has 1001, and that is how someNumber() has been described. Nobody says how the number is chosen, only that i' is in the set. The middle state has exactly one. The done state has none, and that is how a state machine halts. Nondeterminism and termination need no special machinery, since both are just the shape of a formula.
