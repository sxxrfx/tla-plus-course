The diagram is what you are installing. Your module goes to a parser, which checks that the text is legal TLA+. TLC then reads the module along with a model, a small set of choices about what to run: which formulas are Init and Next, and what to check. The red boxes are the two places errors come from, and they tell you different things. If the parser complains, TLC never ran.

Where to look

Lecture 3 opens with a tour of resources. Most of them start from the TLA+ home page, and most of the documentation is in PDF.

  • The Summary of TLA+ is a cheat sheet. Lamport says to download and print it, and that is good advice.
  • Specifying Systems, the TLA+ book, is a useful reference. It was written before the Toolbox existed, so it says nothing about the Toolbox.
  • The TLA+ Google group is where to find out what is happening in the community and to ask other users for help.

Installing the tools

The lecture installs the Toolbox, the IDE for creating specs and running tools on them. The steps it describes are to install Java if you don't have it, download a zip file and extract it, and install LaTeX, which the pretty-printer needs. The pretty-printer produces the typeset form you see on the slides, with ∧ and ∈. If you follow along in the videos, the Toolbox page has the current instructions.

The current option is the official TLA+ VS Code extension. Follow its setup guide. You can also skip editors altogether: download tla2tools.jar from the official releases and run TLC from a terminal. The core tools currently require Java 11 or later.

Whichever you choose, the lectures' ideas are the same. When the Toolbox has you click “Add” under Invariants, a .cfg file has a line for it, as you'll see in the next few lessons. Here is the command form, for a module and config named Name:

java -cp tla2tools.jar tlc2.TLC -config Name.cfg Name

TLC checks a finite model. It can run many useful specs, but it is not a theorem prover, and a model whose states never run out, such as an unbounded counter, can't be fully searched. Keep the models small; every spec in the first lectures has few states.

Predict: your run stopped because the machine ran out of memory, with no violation so far. Did your check pass?

No. The search is incomplete, so you can report only that nothing was found in the part it reached. Shrink the model or add resources and rerun. “No error” counts only when exploration finished.

The rest of the toolkit

  • Help pages. In the lecture, Lamport asks you to read the Toolbox's Getting Started help before the next video and to browse the other sections when you can. If you use the extension, read its documentation the same way.
  • TLAPS, from {{lesson:why}}, checks formal proofs written in TLA+. It can check proofs of real algorithms, but few engineers will use it. {{lesson:proofs}} comes back to proof.
  • Unicode display. Most engineers prefer the ASCII form of their specs; Lamport says he uses the pretty-printed form only for publication. The lecture says a Unicode option was planned for those who want to see ∈ while editing. Check the current documentation for your editor, because the lecture can't tell you what exists today.
