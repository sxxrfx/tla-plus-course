Inside Paxos Commit is one small agreement problem.

You've seen Paxos Commit run one decision per RM. Each of those decisions is an instance of consensus: a group chooses one value, and two different values are never chosen. This lesson separates consensus from commit, then breaks its key rule so you can see why the rule exists.

Read the diagram from the left. Each RM has its own instance with its own acceptor votes. Commit is a small rule on top of the results: all "prepared" gives Commit, and any "aborted" gives Abort. Everything difficult is in the instances, so you can study one of them alone.

While you watch

This lesson's experiment gives you the means to. Everything about one instance and Raft here is added to the lecture.

One instance

The module below cuts PaxosCommit down: no RMs and no ins field. Values are just "X" and "Y", and with no reports a leader may propose either. Ballots start at 1 since no RM owns ballot 0. Its contract is:

Chosen(v) == \E b \in Ballot, MS \in Majority :
               \A a \in MS : [type |-> "2b", bal |-> b, val |-> v, acc |-> a] \in msgs
Agreement == \A v, w \in Value : Chosen(v) /\ Chosen(w) => v = w

Chosen is derived from the votes in msgs, so no process has to know it. A value can be chosen while everyone is still unaware. A model where nothing is ever chosen also satisfies Agreement, so progress needs separate assumptions.

Show the complete module
----------------------------- MODULE OneDecree ------------------------------
\* One Paxos consensus instance, cut out of PaxosCommit: the ins field and the
\* RMs are gone, and with no earlier evidence a leader may propose any value.
EXTENDS Integers
Maximum(S) == IF S = {} THEN -1
                        ELSE CHOOSE n \in S : \A m \in S : n >= m
CONSTANTS Value, Acceptor, Majority, Ballot
ASSUME /\ Ballot \subseteq Nat \ {0}
       /\ \A MS1, MS2 \in Majority : MS1 \cap MS2 # {}
VARIABLES aState, msgs
vars == <<aState, msgs>>

Init == /\ aState = [a \in Acceptor |-> [mbal |-> 0, bal |-> -1, val |-> "none"]]
        /\ msgs = {}
Send(m) == msgs' = msgs \cup {m}

Phase1a(b) == /\ Send([type |-> "1a", bal |-> b])
              /\ UNCHANGED aState

Phase1b(a) ==
  \E m \in msgs :
    /\ m.type = "1a"
    /\ aState[a].mbal < m.bal
    /\ aState' = [aState EXCEPT ![a].mbal = m.bal]
    /\ Send([type |-> "1b", mbal |-> m.bal, bal |-> aState[a].bal,
             val |-> aState[a].val, acc |-> a])

Reports(b, MS) == {m \in msgs : /\ m.type = "1b" /\ m.mbal = b /\ m.acc \in MS}
FromAll(b, MS) == \A a \in MS : \E m \in Reports(b, MS) : m.acc = a
NotUsed(b) == ~\E m \in msgs : m.type = "2a" /\ m.bal = b

\* The rule that matters: repeat the value of the highest ballot reported.
Phase2a(b) ==
  /\ NotUsed(b)
  /\ \E MS \in Majority, v \in Value :
       LET maxbal == Maximum({m.bal : m \in Reports(b, MS)})
       IN  /\ FromAll(b, MS)
           /\ \/ maxbal = -1
              \/ \E m \in Reports(b, MS) : m.bal = maxbal /\ m.val = v
           /\ Send([type |-> "2a", bal |-> b, val |-> v])
  /\ UNCHANGED aState

\* The broken version: same quorum, but the reports are ignored.
Phase2aForget(b) ==
  /\ NotUsed(b)
  /\ \E MS \in Majority, v \in Value :
       /\ FromAll(b, MS)
       /\ Send([type |-> "2a", bal |-> b, val |-> v])
  /\ UNCHANGED aState

Phase2b(a) ==
  \E m \in msgs :
    /\ m.type = "2a"
    /\ aState[a].mbal <= m.bal
    /\ aState' = [aState EXCEPT ![a].mbal = m.bal,
                                ![a].bal  = m.bal,
                                ![a].val  = m.val]
    /\ Send([type |-> "2b", bal |-> m.bal, val |-> m.val, acc |-> a])

Next == \/ \E b \in Ballot : Phase1a(b) \/ Phase2a(b)
        \/ \E a \in Acceptor : Phase1b(a) \/ Phase2b(a)
NextForget == \/ \E b \in Ballot : Phase1a(b) \/ Phase2aForget(b)
              \/ \E a \in Acceptor : Phase1b(a) \/ Phase2b(a)

Chosen(v) == \E b \in Ballot, MS \in Majority :
               \A a \in MS : [type |-> "2b", bal |-> b, val |-> v, acc |-> a] \in msgs
Agreement == \A v, w \in Value : Chosen(v) /\ Chosen(w) => v = w
OneValuePerBallot == \A m1, m2 \in msgs :
  (m1.type = "2b" /\ m2.type = "2b" /\ m1.bal = m2.bal) => m1.val = m2.val
=============================================================================
INIT Init
NEXT Next
CONSTANTS Value = {"X", "Y"}
          Acceptor = {"A", "B", "C"}
          Majority = {{"A", "B"}, {"A", "C"}, {"B", "C"}}
          Ballot = {1, 2}
INVARIANT Agreement
INVARIANT OneValuePerBallot
CHECK_DEADLOCK FALSE

With three acceptors, two values, and ballots {1, 2}, TLC reports no error, 3921 distinct states. That run also checks OneValuePerBallot: all votes in one ballot have the same value. The NotUsed guard allows just one 2a message per ballot, and acceptors repeat only what it says. That's why the CHOOSE Lamport points at can't matter. Messages with the same highest ballot agree.

Worked failure: a new ballot forgets the old vote

Now replace Phase2a with Phase2aForget, which still needs reports from a majority but ignores what they say:

Phase2aForget(b) ==
  /\ NotUsed(b)
  /\ \E MS \in Majority, v \in Value :
       /\ FromAll(b, MS)
       /\ Send([type |-> "2a", bal |-> b, val |-> v])
  /\ UNCHANGED aState

TLC reports Agreement violated in a 13-state trace. These are its last few states, showing each acceptor's last vote.

By state 12, A and B voted Y in ballot 2, so Y is chosen. In the last column, C votes X in ballot 1: B's X vote in ballot 1 is still in msgs, so {B, C} also chose X. In state 9 B reported "I voted X in ballot 1" to the ballot 2 leader. That report was the warning, and the broken rule ignored it. The real rule would have made ballot 2 propose X, and then both ballots agree.

Quorum overlap was present the whole time: {A, B} and {B, C} share B. So overlap alone doesn't save you. It creates a place where evidence can pass between ballots, and the protocol must also obey it. This is the point {{lesson:replication}} ended on: a place to look isn't yet an answer.

Predict: if B restarts and forgets its promise and last vote, is overlap still enough?

No. B would report no vote, and the leader of ballot 2 may then propose Y, the same failure by a different path. The spec has no action that loses aState, which is an assumption: those fields must survive a restart. A recovery action in your model must keep exactly what this argument relies on.

From one value to a log

Paxos Commit runs a fixed set of instances, one per RM. A replicated service needs an ordered list of operations, so it runs one consensus decision per log position. Replicas apply chosen operations in order.

In the diagram, a column is one decision. S3 lags behind but it holds no conflicting value in any filled column. Agreement per position is what a replicated log needs, and new questions come with it: who proposes, what happens to entries no majority has, and what can be discarded.

Raft is a widely used protocol for replicated logs. It separates leader election, log replication, and safety. A term plays a role like a ballot; it isn't a wall-clock time. To study it, follow one committed entry across a leader crash and an election, and ask what prevents an elected leader from lacking that entry. "A majority elected it" is not the whole answer: Raft restricts which logs can win. Use its published spec rather than reconstructing it from a diagram.
